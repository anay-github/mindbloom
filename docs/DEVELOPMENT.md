# Development guide

[Back to README](../README.md) · [Project notes](PROJECT_NOTES.md) · [Live demo](https://mindbloom-ai-app.lovable.app/)

## Start locally

Use Bun and the committed `bun.lock` to keep dependency resolution consistent.

```sh
git clone https://github.com/anaypandit/mindbloom.git
cd mindbloom
bun install --frozen-lockfile
cp .env.example .env
```

Replace the placeholder values in `.env` with configuration for your own Supabase project, then run:

```sh
bun run dev
```

Open the URL printed by Vite. The main routes are `/`, `/student-dashboard`, `/counselor-dashboard`, and `/signin`.

## Environment configuration

[.env.example](../.env.example) documents the exported project's configuration names.

| Variable | Purpose |
| --- | --- |
| `VITE_SUPABASE_URL` | Public project URL used by the browser client. |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Publishable client key for the same project. |
| `SUPABASE_URL` | Server-side project URL and SSR fallback. |
| `SUPABASE_PUBLISHABLE_KEY` | Publishable key used by server authentication middleware and the SSR fallback. |
| `VITE_SUPABASE_PROJECT_ID`, `SUPABASE_PROJECT_ID` | Project identifiers retained in the export template. |

Use the same project for the browser and server settings. Values prefixed with `VITE_` are public and can be included in the browser bundle. A Supabase service-role key must never be put in a `VITE_` variable or committed to the repository. The optional server admin client reads `SUPABASE_SERVICE_ROLE_KEY` only when used; it is not part of the documented dashboard demo setup.

The Supabase clients and middleware are scaffolding. Supplying configuration does not turn the demonstration sign-in screen into a production authentication flow. `.env` files are excluded by [.gitignore](../.gitignore); the placeholder example is intentionally tracked.

## Available commands

These commands come from [package.json](../package.json).

| Command | Purpose |
| --- | --- |
| `bun run dev` | Start the Vite development server. |
| `bun run build` | Build the application using the configured TanStack/Nitro integration. |
| `bun run build:dev` | Build in development mode. |
| `bun run preview` | Run the configured Vite preview command. |
| `bun run lint` | Run ESLint. |
| `bun run format` | Run Prettier in write mode across the repository. |

There is currently no automated test script in the package manifest. Use formatting on the files you edit, and review the diff before committing a whole-repository format pass.

## How the demo data flows

Routes render sample student records and local UI state. `analyzeStudent` in `mindbloom-ai.ts` compares recent sample signals with an earlier baseline, applies explicit thresholds, and returns explanatory summaries and support categories. Counselor helper replies also include deterministic demonstration logic.

Skill preferences, completion, XP, quests, and support alerts use browser-local storage helpers. Other dashboard state lives in memory or session storage. This does not provide a shared school database or authenticated multi-user system. Changes in one browser should not be assumed to sync to another device.

## Verification and contribution workflow

For code changes, install from the lockfile, run the relevant lint and build commands, and exercise the affected dashboard or route with sample data. Include the checks performed and any remaining limitations in the change description. Keep credentials, private student information, and generated build output out of commits.

For the **November 12, 2026 documentation review**, the live landing page and both dashboards loaded, skill preferences produced a path, and the sample counselor alert and explanation controls were explored. Documentation commands were checked against the source and package scripts, and repository-relative links were validated. A fresh local build and lint run were not performed because Bun and Node were not available in the editing environment.
